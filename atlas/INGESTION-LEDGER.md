# Ingestion ledger — merged Niagara atlas collection

**The authoritative record of what is in the merged collection, where each
layer came from, and when it was last pulled.** Regenerated by
`scripts/update_ledger.py` after every fetch. One row per source layer.

Companion to [sources/sources.json](sources/sources.json) (machine registry —
only gains an entry once a layer is ingested and rendered),
[sources/manifest.json](sources/manifest.json) (machine twin of this file),
[CANDIDATES.md](CANDIDATES.md) (the numbered menu),
[RECON-2026-08-22.md](RECON-2026-08-22.md) and [BACKLOG.md](BACKLOG.md).

`#` is the candidate number from CANDIDATES.md and is **stable** — quote it
when adding, removing or re-pulling a layer.

## Raster and imagery — a different kind of source

The historical imagery in §G is **not a downloadable dataset**. Each is an
ArcGIS map or image service that renders tiles on demand; there is no single
file that constitutes "the layer". Where a vector sublayer exists it holds only
the mosaic's **extent footprint** — #107 returned one polygon, #109 and the
1950s/1970s topographic series returned zero features. Service metadata
(extent, spatial reference, tile scheme, pixel size) is captured as
`*.service.json`; the imagery itself is consumed as a tile layer at display
time, or exported at a chosen resolution as a rendering rather than as data.

**Brock University's server (`terra.library.brocku.ca`) is behind a Cloudflare
bot challenge** and returns HTTP 403 to automated requests — intermittently,
which is why some Brock layers resolved and others did not. This is a
deliberate access control and is not worked around. The 1934/1954/1965/1972
air photo mosaics remain the most valuable historical evidence found; getting
them means loading in a browser or asking the **Brock Map Library** directly,
which as a public academic map library is the reasonable route.

## Rules for amending this file

1. **Regenerate, don't hand-edit** — run `scripts/update_ledger.py`. The
   amendment log is the one part carried across regenerations.
2. **One row per source layer**, never per candidate — a candidate bundling
   three by-laws gets three rows, so a partial pull stays visible.
3. **`Verified` and `Pulled` are different facts** and must not be conflated.
4. **Record counts are observed**, never estimated.
5. **Blocked layers stay listed.** Removing one hides the gap.
6. **A layer only enters `sources/sources.json` when it is actually rendered**
   in the atlas, with its own probe and licence line. This ledger runs ahead
   of that registry by design.
